# Minibox NES 实现与验收计划

## 目标与完成标准

在现有 Minibox 应用中增加可退出、可重复加载的单人 NES 模拟器，
不改变硬件接线，不破坏闲聊、电台、设置、时钟和已有游戏。
项目定位为个人娱乐、非商业使用，不默认开展商业发布合规审查，
不反复询问商业授权；第三方代码原有许可证仍保留。
只使用用户明确指定的 ROM 文件或链接，不自行搜索或替换其他游戏。
“最优”以当前硬件约束下的正确性、稳定性、输入体验和可测性能为准，
不是选择 README 宣传帧率最高的项目，也不是支持 mapper 数量最多就算完成。

本文区分源代码核查、主机测试、固件构建与实板验收。
主机测试和构建都不能证明实体屏幕方向、实际声音或商业游戏兼容性。
没有用户明确授权，不烧录、不修改分区布局、不提交或推送。
用户随后已授权完成后烧录测试，并要求避免过多不必要的离线测试。
因此本轮不继续扩大离线矩阵：收尾已有核心/摇杆回归，修复实际失败后，
直接增量构建、COM8 `app-flash` 和短时串口观察，保留设备 storage。
下文完整兼容性与性能检查清单是后续实板验收依据，不表示本轮全部执行。

## 硬件与既有软件边界

| 约束 | 实现要求 |
|---|---|
| ESP32-S3 N16R8，8 MiB Octal PSRAM | ROM 与大帧缓冲显式放 PSRAM；失败时报告错误，不挤占内部 DMA 内存 |
| ST7796，480×320，SPI 最高 40 MHz | 复用官方 LCD 组件及现有 LVGL 驱动，禁止同时直接写屏 |
| GPIO1/2 摇杆，无按压接线 | 复用启动校准和实际轴映射；菜单四方向与 NES 八方向分开解析 |
| GPIO4/5/6/7 四键 | NES A/B/Select/Start；Select+Start 长按退出，释放后才恢复菜单 |
| MAX98357，GPIO39/40/41，GAIN42，SD47 | 复用 `audio_io`；不创建第二套 I2S，不与麦克风并行 |
| 没有 SD 卡接口 | 从现有 storage SPIFFS 根目录加载，不移植参考项目 SD 接线 |
| 多应用共存 | 游戏占用音频时阻止自动播报、联网阻塞操作；退出后完整恢复 |
| 私密配置与 ROM 共用 storage | 不读取/输出配置内容；明确告知更新 storage 会覆盖配置与存档 |

## 三个参考仓库的核查结论

### 1. espressif/esp32-nesemu

来源：<https://github.com/espressif/esp32-nesemu>，本地 revision `693e378`。

已核查核心路径：
`components/nofrendo/nes/nes.c`、`nes_rom.c`、`nes_mmc.c`、
`nes_ppu.c`、`nesinput.c`、`cpu/nes6502.c`、
`sndhrdw/nes_apu.c`、`bitmap.c` 和 `components/nofrendo-esp32` 适配层。

**适合采用：** 可独立编译的 C CPU/PPU/APU、扫描线接口、索引色画面、
mapper 接口，以及较小的嵌入式内存需求。与本项目 ESP-IDF/C 结构最接近。

**不能原样采用：**

- 原 `nes_rom.c` 的 ROM 来源是无长度参数的内存指针，trainer 路径误改指针变量，
  PRG/CHR 指向输入区域而释放路径仍逐个 `free`；不能用于可反复加载的文件浏览器。
- 原 `nes_insertcart` 失败时释放局部 machine 指针，调用方无法得知所有权已经失效；
  必须统一由实例拥有者清理。
- `nes.c` 跳帧时不走 `vid_flush`，旧适配器音频生成却挂在该路径；
  不能将画面提交与 APU 推进绑定。
- CPU 存在直接读取未对齐 16-bit 数据、跨 bank 和零页边界假设，
  需要在当前 Xtensa 工具链与主机回归中验证。
- 手柄连续串行读取和 strobe 高电平行为需要补充验证；不能只测试菜单按键事件。
- MMC1/MMC3 是旧近似实现，不能仅因为 mapper 在列表里就宣称所有对应游戏兼容。

**结论：** 作为受控、精简的核心基线；替换加载、时序和平台适配层，
对上述已识别路径修复并增加针对性回归，不导入整个旧模拟器 GUI。

### 2. Shim06/Anemoia-ESP32

来源：<https://github.com/Shim06/Anemoia-ESP32>，本地 revision `7cdf281`。

已核查 `Anemoia-ESP32.ino` 的任务/帧循环/I2S/退出流程，
`src/nes.cpp`、`core/cartridge.cpp`、`core/cpu6502.cpp`、
`core/ppu2C02.cpp`、`core/apu2A03.cpp`、`core/bus.cpp`，
以及 ROM 后端接口、运行配置与 README 的性能条件。

**值得借鉴：**

- 40 MHz SPI 屏采用隔帧输出，模拟推进和显示刷新是两个指标。
- 持续读取手柄状态，Start+Select 作为应用层组合操作。
- ROM CRC32 用作存档身份，避免仅依赖显示文件名。
- 按期限控制帧率、明确区分模拟耗时与显示耗时。
- 小块/DMA 视频流水线与无 PSRAM 运行设计，可作为后续性能优化备选。

**不照搬：**

- Arduino、TFT_eSPI、SD/LRU/Flash mmap 后端与本项目平台条件不同；
  本机已有 PSRAM，不需要为无 PSRAM 目标引入 SD 换页缓存。
- 独立 APU task 与 CPU 寄存器访问的同步方式需要重新设计，
  不能把其任务拆分直接搬进已有音频服务。
- 暂停菜单、演示模式等通过重启恢复，不符合本项目多应用无重启退出需求。
- 自动格式化 LittleFS、背光 PWM、原引脚定义均不符合当前约束。
- GPLv3 项目代码不能不审查许可证就混入 GPLv2 标注的旧核心。

**结论：** 借鉴设计与性能约束，不复制其 GPLv3 源码。
完整换用该内核不是本轮默认方案；只有合法 ROM 的兼容性/性能证据证明
当前内核无法达标，才单独评估替换成本与许可证，不并存两套未验证内核。

### 3. derdacavga/Esp32-S3-nes-emulator-by-DSN

来源：<https://github.com/derdacavga/Esp32-S3-nes-emulator-by-DSN>，
本地 revision `030c4b8`。

已核查 `src/nes_rom.c`、`mem_shim.c`、`osd.cpp` 的加载/音频/输出路径、
`nes.c` 的帧循环、`tft_driver.h` 和示例启动流程。

**值得借鉴：**

- PRG/CHR 分别分配 PSRAM，并检查读取长度，优于原始指针式加载。
- 用 RGB565 查找表转换索引帧；MAX98357 使用左右声道相同的 PCM。
- 输出显示传输耗时，有助于确定瓶颈，而不是只看总 FPS。
- ROM 列表分页与局部重绘思路。

**不照搬：**

- `osd.cpp:666–744` 将音频生成放在 `vid_flush`，而 `nes.c` 跳帧不走
  flush；因此跳帧与声音推进耦合，不能直接沿用。
- 16 kHz 每帧整数采样数有余数，且 I2S 写入使用零等待并未验证完整写入；
  当前方案选择 24 kHz/60 Hz 的整帧采样，显式检查输出长度/错误。
- `mem_shim.c` 忽略 fast-memory 参数，失败又回落到普通堆；
  多应用固件中不能让大 ROM 意外耗尽 DMA 所需内部 RAM。
- ST7789、80 MHz SPI、SD 和按键引脚均不同；`tft_driver.h` 不是本项目屏幕驱动。
- 该仓库是同一旧 Nofrendo 家族，并不能独立证明原核心 mapper 的准确性。

**结论：** 参考 S3 内存分配、转换和观测方式；不导入其 Arduino/GPLv3 平台源码。

## 当前技术方案

| 项目 | 方案与理由 |
|---|---|
| 内核 | 单实例 Nofrendo C 核心，显式 open/frame/close，单个 worker 拥有 CPU/PPU/APU |
| ROM | 完整读取到 PSRAM；先验证 iNES 头、精确长度、大小、mapper 和 RAM 约束 |
| 范围 | NTSC iNES 1.0、单人、常见 mapper 0/1/2/3/4/7/66；其他格式明确拒绝 |
| 图像 | 256×240 最近邻放大至 426×320，按电视 4:3 比例居中，左右各 27 像素黑边、不裁剪；LVGL 是唯一显示写入者 |
| 时序 | I2S 缓冲水位驱动约 60 次/秒模拟、每两帧尝试提交；邮箱待处理或音频不足两帧时跳过 PPU 绘图，不丢 CPU/APU 推进 |
| 音频 | 每帧 400 个 24 kHz 单声道样本，按 CPU 周期分段生成；NES 使用 3×256 帧 DMA，跨帧拼满块再写，半幅输出 |
| 保存 | 有电池标志的 8 KiB SRAM，以 ROM CRC32 命名；临时文件、旧备份、失败提示 |
| 生命周期 | 先检查音频占用，加载失败统一回收；正常退出停音频、存档、释放、回列表 |
| 许可证 | 保留导入文件声明、AUTHORS、GPLv2/LGPLv2 文本及修改说明；发布前单独核对义务 |

原始 RGB565 帧为 122,880 字节；放大至 426×320 后为 272,640 字节。
放大后的 30 fps 约 8.18 MB/s，超过 40 MHz SPI 的理论 5 MB/s；
当前按 16 行条带刷新变化范围，局部更新目标最高 30 fps；整屏滚动仍不能
达到 30 fps。15 fps 全屏约 4.09 MB/s，还需留协议、DMA 和 LVGL 开销。
不为追求数字超频屏幕，也不将显示帧率与 CPU/APU 推进绑定。

索引帧连同 overdraw 约 65 KiB，双缓冲索引邮箱 120 KiB，
LVGL 放大后的视频图像约 266 KiB，
ROM 上限 2 MiB；另有原有 UI、音频 ring、系统和网络内存。
这是设计预算，不是设备实测空闲值。

## 分阶段任务及检查门槛

### A. 固定来源与平台边界

- 记录以上版本、源码路径、许可证差异和明确不复用的部分。
- 保留当前引脚、分区地址、诊断启动选项。
- 只处理用户指定的 ROM；如实区分来源记录、实际下载、加载与实板测试状态。
- 门槛：项目不依赖三个本地参考目录，也不新增 Arduino 或外设驱动。

### B. 内核与加载安全

- 正常、截断、错误 magic、零 PRG、NES 2.0、PAL、未知 mapper、
  trainer、CHR-ROM/CHR-RAM 的行为都必须明确。
- 反复 open/close、加载失败后再加载、不同卡带之间切换不得双重释放或复用旧状态。
- 验证 CPU 边界读取、PPU ROM 写保护、控制器 latch/strobe。
- 对所选 mapper 核查初始化、切换模式和银行映射；不足的实现先修复再宣称支持。
- 保存测试涵盖读取、覆盖、备份恢复、损坏数据、同名不同 ROM 的隔离。
- 门槛：自制 ROM 执行能证明 CPU 工作、PPU 产出画面、APU 产出 PCM，
  而不是仅证明文件可以读开。

### C. 输入体验

- 单一函数集中执行物理 X/Y 到屏幕方向映射，不在 NES 另写一套反转规则。
- 菜单使用四向主轴吸附，换轴需要 15 个百分点优势。
- NES 八向：副轴达到主轴 65% 才进入斜向，进入后低于 45% 才退出。
- 25% 进入、15% 回中释放；复用每次八个 ADC 样本平均，不增加显著滤波延迟。
- 保留持续按键和斜向组合；长按退出后必须等待释放，避免按键穿透到菜单。
- 门槛：覆盖四向、四斜向、偏斜、边界抖动、回中和快速反向；
  实物方向最终仍需手持设备确认，不根据 GPIO 名称猜测。

### D. 显示、音频和应用协作

- 视频更新与 LVGL 刷新互斥；繁忙时允许丢一次显示提交，不阻塞音频帧推进。
- 确保大图像数据已复制到受控缓冲后才能被 LVGL 使用，无跨任务悬空指针。
- APU 只在 emulator worker 中运行，I2S 仅由已有音频任务拥有。
- 游戏启动前预填少量 PCM；每次检查实际写入长度和播放状态。
- 错误退出和正常退出都要恢复 UI、音频 ownership 和主应用调度。
- 门槛：编译无新增警告；正常应用和诊断构建的条件依赖不互相破坏。

### E. 性能与实板验收

- 先完成最小主机回归及 ESP-IDF 5.3.5 构建，不建立额外复杂测试框架。
- 用户授权烧录后，以有权使用的 NROM、UxROM、MMC1、MMC3 游戏分别观察：
  进入游戏、持续运行、声音、方向、组合键、退出再进、返回其他应用。
- 记录 emulated fps、submitted fps、显示繁忙丢帧数、音频 underrun、
  剩余内部堆/PSRAM 和最大可分配块。
- 分别测 CPU、PPU、像素转换、锁等待与 SPI；只优化真实瓶颈。
- 候选优化顺序：不阻塞显示提交 → 减少转换/无用重绘 → 热点布局/查表 →
  必要时评估分块 DMA。不要先改成双内核、超频或绕开 LVGL。
- 连续加载/退出后资源不得持续减少；实板未完成前明确标注待验证。

### 后续放大与音频修正

再次对照用户指定的两个本地参考项目：Anemoia 的 `src/nes.cpp` 直接 DMA
输出原尺寸像素，`Anemoia-ESP32.ino` 配置小 DMA，
`src/core/apu2A03.cpp` 按时钟生成样本、以完整音频缓冲阻塞写入；
DSN 的 `src/osd.cpp` 仍在 `vid_flush` 中合成音频并零等待写入。
两者都没有可直接复用的 480×320 缩放方案，因此借鉴音视频解耦和完整块供给，
不导入 Arduino 驱动、独立 APU 并发任务或 GPLv3 源码。

初版源码将完整画面最近邻放大至 426×320，并按带宽降低视频提交频率。
音频修正包含 CPU 周期同步、播放水位驱动模拟、NES 专用小 DMA 和跨帧整块供给。
原来的整帧末合成会折叠帧内寄存器变化；400 样本突发供给还可能留下未填满
的 DMA 块，被驱动回收而出现间隙。独立帧定时也不再与 I2S 时钟竞争。
新增自制 ROM 回归比较帧中途停音与分段合成的 PCM，覆盖读寄存器同步和输出边界；
这些检查不能证明坦克、桌球的实板听感已恢复。此初版更新随后随
`2af1569` 完成构建和 COM8 完整烧录，写入校验通过。
本次自制 ROM 核心回归及新增音频时序回归通过，最近邻映射覆盖全部
256 列与 240 行；ESP-IDF 5.3.5 构建通过，无编译警告。
应用大小 2,008,400 字节，原 2 MiB 分区剩余 88,752 字节（约 4%），
仍有分区接近满载的容量提示，未改动分区。

用户实测反馈放大后刷新偏低、桌球瞄准动作仍伴随周期性卡音。
进一步核查确认旧版固定四帧一次提交（上限 15 fps），且放大转换在
